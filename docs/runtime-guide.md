# Agent 运行说明

CourseMate 提供网页和 CLI 两个入口。以下以总结课件为主线，说明从启动、提问到查看结果的完整过程；后面给出日历、邮件和自测的操作示例。

## 1. 启动和连接模型

首次运行需要 Python 3.10+。在项目目录执行：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
.venv/Scripts/python.exe app.py check
.venv/Scripts/python.exe app.py serve --port 8765
```

打开 http://127.0.0.1:8765，进入“设置”，填写 Base URL、模型名和 API Key。DeepSeek 官方地址为 `https://api.deepseek.com`，模型名从账户实际可用列表选择。保存后使用连接测试；成功时可以看到模型和用量等回执。连接测试会发出真实请求，因此不能用离线测试结果代替。

配置保存在本机 `.env`，不会随源码上传。真实运行使用 `live` 模式；`demo` 只用于固定演示，不发送模型请求。网页与 CLI 为独立进程，修改模型配置后应重新启动已打开的 CLI。

## 2. 导入资料并确定范围

在“资料库”上传课程文件，支持文字型 PDF、PPTX、DOCX、TXT 和 Markdown。解析后的资料可通过列表查看，Agent 检索时读取这些文件的实际内容。扫描图片形式的 PDF 不能依靠文字解析器直接识别。

回到“学习对话”，选择需要使用的资料，然后输入：

> 总结这份课件，按主题列出要点，并标出原文出处。

如果资料库中有多份 PPT，而用户只说“这个 PPT”，系统会先提供文件选择。选定范围后再继续，避免总结错文件。也可以在问题中明确写出文件名。

## 3. 一次请求怎样执行

提交问题后，编排层将问题、系统提示词、资料范围和最近的有效会话交给模型。模型通过标准 Function Calling 请求工具，程序负责执行真实操作：

1. 必要时用 `list_documents` 确认文件；用 `search_documents` 检索相关内容，或直接请求读取指定文件。
2. 用 `read_document` 取得原文片段及定位信息。PPTX 对应幻灯片编号，PDF 对应页码，文本对应行号等位置。
3. 工具结果带着对应的 `tool_call_id` 回传模型。模型发现材料不够时，可以继续读取；调用顺序由任务决定，并不是每次固定执行相同脚本。
4. 模型组织回答后，程序检查引用来源和位置，再核对段落与原文是否一致。执行有轮数和超时限制，异常不会无限重试。

界面会显示执行进度。生成中的文字只是草稿；完成核对后才形成最终结果。来源不足时可能要求补充资料；只有部分段落能核实时会标明“部分回答”，不能把它当作完整总结。

## 4. 查看、追问和保存结果

在回答处打开原文引用，可回到对应资料和位置。“工具过程”用于查看工具名称、参数与返回结果；证据核对用于检查段落依据。如果内容不合预期，先检查选中的文件和实际读取范围，再补充问题，例如“只总结第 3 至 6 张幻灯片”。

同一会话可以继续追问。历史对话帮助理解上下文，但新回答仍应读取当前相关证据。需要生成笔记时，开启保存权限并明确要求保存为 Markdown；文件写入 `outputs/`，网页可预览或下载。任务、日历和草稿等学习事务另走预览确认流程，不因模型提出建议就立即落库。

## 5. CLI 的完整操作示例

打开另一个终端，在项目目录启动：

```powershell
.venv/Scripts/python.exe app.py chat
```

进入交互界面后，依次尝试以下输入。文件名应替换成自己的资料：

```text
/docs
/use Vibe Coding(1).pptx
总结这份课件，解释 Agent 调用外部工具的过程。
/sources
/trace
/review
继续用一个例子说明模型和工具各自负责什么。
```

`/docs` 查看资料，`/use` 限定范围，普通文本发送问题。回答后 `/sources` 查看来源，`/trace` 查看上一轮调用的参数和结果，`/review` 查看证据核对。输入 `/sessions` 列出会话，再用 `/resume 编号` 恢复；`/new` 开始新会话。

Enter 发送，Esc+Enter 换行，Tab 补全斜杠命令，上下方向键浏览输入历史。Ctrl+C 可中断接收中的回答，但已经发送给服务端的请求可能仍在处理。`/help` 查看完整命令，`/quit` 退出。CLI 支持连续对话和工具进度展示，面向学习任务，不执行任意 Shell 命令。

## 6. 日历、邮件和自测怎样操作

| 场景 | 用户操作 | Agent 的处理与最终结果 |
| --- | --- | --- |
| 安排学习时间 | 导入本地 ICS 日历并录入任务，提问“找一个 30 分钟空档复习这份课件” | 读取任务与日历，寻找空闲时段，生成安排预览；确认后保存，并重新检查冲突 |
| 起草邮件 | 提问“根据刚才的学习内容，起草一封向老师请教 MCP 的邮件” | 生成待确认草稿；保存后到邮件草稿页编辑、复制或导出 `.eml`，不会自动发送 |
| 复习自测 | 选定课件，提问“根据这份资料出几道自测题，并保留依据” | 读取原文后生成题目提案；确认后在复习页逐题作答、查看参考答案并记录自评 |

CLI 中可用 `/study` 查看学习记录，`/pending` 查看提案，`/confirm 编号` 确认，`/reject 编号` 拒绝。确认学习事务时才提交数据库；重复确认不会重复创建相同记录。

## 7. 常见状态和处理方法

| 状态 | 含义和处理方法 |
| --- | --- |
| 等待选择资料 | 目前无法确定所指文件，点击资料名称或用 `/use` 指定 |
| 正在调用工具 | 正在读取本地文件或执行已启用技能，可查看进度 |
| 待确认 | 变更尚未生效，先核对内容再确认或拒绝 |
| 部分回答 | 部分内容已有依据，其余内容未通过核对，查看缺失提示并补充资料 |
| 引用或证据核对失败 | 没有足够可核对内容，查看工具过程和原文；不要把草稿当成完成答案 |
| 模型连接失败 | 检查地址、账户可用模型、密钥和网络；使用连接测试定位 |

运行记录保存在 `logs/`，课程文件在 `data/`，笔记在 `outputs/`，会话及学习数据库在 `local/`。这些本地数据与 `.env` 不进入源码包。真实调用会把问题和相关工具上下文发送给配置的模型平台。

## 8. 怎样验证运行结果

离线回归用于验证程序逻辑：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

真实模型验收使用以下脚本，会产生 API 用量：

```powershell
.venv/Scripts/python.exe scripts/live_study_acceptance.py --live
```

判断 Agent 是否完成任务，需要同时检查结果、工具调用和原文依据。连接测试成功只能说明接口可用；测试用例通过不能替代真实模型运行；有模型响应也不等于任务已完整完成。
