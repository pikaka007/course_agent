# AI 辅助开发记录

本记录描述本次 Codex 会话中实际完成的工作，不伪造学生手写经历或额外 AI 对话。可将本次聊天记录作为原始开发过程证据。

## 用户提供的约束

用户给出课件、实验报告模板和三个技术要求，并要求把正式交付与学习说明分到两个文件夹。用户随后要求身份信息留空、密钥不显式写入项目，并最终确认使用 `deepseek-v4.1-flash-1017`。

## 需求到实现

Codex 读取课件第 137–138 页和报告模板，确认需要至少两种技能、MCP 或标准 Function Calling、AI 编写脚手架、五页以内报告、3–4 张执行截图与具体反思。随后选择“课程资料学习助手”，生成 Python 配置、HTTP 请求、工具 Schema、文档解析、调用循环、网页和测试。核心行为独立保存在 `prompts/system.md`，便于人工阅读和修改。

项目未引入额外 Agent 框架：标准库即可表达 Function Calling 的完整闭环，便于课程答辩逐行解释。AI 生成的是可检查的源码，而不是只有一个聊天页面的演示。

## 实际遇到的问题与修正

1. **服务型号不一致。** 最初用户提到 Flash 1027；服务的 `/models` 列表没有这个名字。先核对服务返回值，再由用户确认改用 Flash 1017，没有猜测模型名后伪造成功。
2. **中文终端编码。** 首次提取 PPTX 文本时，默认 GBK 输出无法编码某些 emoji，导致中断。给执行环境设置 UTF-8，并在 CLI 入口对 stdout 配置 UTF-8；解析得到的文本仍保留 Unicode。
3. **首轮回答过长且引用缩写。** 首次真实运行能完成工具闭环，但回答扩展了非必要主题，并出现 `[幻灯片17]` 这类简写。系统提示词加入默认约 400 汉字和完整来源标记约束，再通过实际笔记任务检查输出。该约束改善格式，不等同于形式化保证模型永不出错。
4. **模板渲染兼容。** 打包的文档渲染脚本依赖 LibreOffice，而机器未安装；Word 自动化也失败。改用已安装 WPS 的后台导出能力生成 QA PDF，再逐页检查图片。原始模板保持不变。

## 代码验证与责任边界

另一个真实检索问题出现在缺失资料测试中：最初的“任一关键词命中”规则让 quantum error correction 命中普通软件 error 页面。模型虽然识别出主题无关，程序仍应减少无效证据。因此改成全部查询词必须出现，并新增多词查询回归测试，再次用真实模型检查缺失资料回答。

针对路径越界、错误参数、损坏文件、无检索结果、重复调用 ID、调用关联、循环上限和只新建不覆盖等边界编写测试，并完成真实模型读取与保存演示。具体结果在 `evidence/`。离线脚本演示明确标为 `scripted-demo-no-llm`，不把它作为模型自主选工具的证明。

人工仍需核对答案是否忠实于原文、选择合适的资料、控制 API 用量，并在提交前填写姓名、学号及远程仓库链接。AI 编写代码并不能替代这些核查。

后续第二版的实际迭代、33项测试及引用检查边界见 `docs/iteration-v2.md`。第一版记录保留原样，不将后续新增功能倒填为最初已实现。
